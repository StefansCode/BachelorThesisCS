\subsection{Adapter}

Ports sind abstrakte Klassen und bilden die Schnittstelle zur Hardware und zur ESP-IDF 
\cite{espidf2026api}.
Adapter sind ihre Implementierung.
Durch das Austauschen der Adapter, lässt sich der Kern unabhängig von 
diesen beiden Faktoren, also auch auf einen normalen PC, testen.
Im Folgenden werden alle Adapter und ihre Funktionen kurz erklärt.


\subsubsection{Digital-to-Analog Converter}
Die Kommunikation zwischen dem DAC und dem ESP32-S3 findet über die 
I2S-API \cite{esp32s3i2s} der ESP-IDF statt.

Die I2S-API ist im Standardmodus mit dem Phillipsformat eingestellt, 
da das, das Standartformat ist, welches der MAX98357A erwartet.

Der Mono-Modus wird verwendet, da der MAX98357A ein Monoverstärker ist.
Das heißt das nur ein Signal gesendet wird, anstatt jeweils eins für 
Links und
eins für Rechts. Das I2S Protokoll sendet zwar immer ein linkes und ein 
rechtes Signal, aber die die I2S-API sendet im Mono-Modus für beide Seiten
das gleiche Signal und es reicht der API ein Signal zu übergeben.
Der MAX98357A erhält also immer ein linkes Signal $L$ und ein 
rechtes Signal $R$ und gibt $(L+R)/2$ verstärkt heraus.

Abtastrate und die Auflösung des 
Signals über eine Initialisierungsfunkion Übergeben.

Um ein Signal zu senden, ruft man die Funktion \lstinline|sendBuffer| auf.
Ihr wird ein Buffer und die Länge des Buffers übergeben. Die Werte 
werden an die API weitergegeben und diese blockiert bis alle Werte 
gesendet wurden. Dadurch wird die richtige Abtastrate eingehalten.

\begin{lstlisting}[language=C++, 
                   frame=single, 
                   caption={Beispiel Code zum Dac Port},
                   captionpos=b]
Dac dac;
bufferLen = 256;
int16_t buffer[bufferLen];
int16_t value;
int main {
    dac.init(32768, 16)
    int16_t value = 0;
    while(1) {
        for(int i=0; i<bufferLen; i++) {
            buffer[i] = value;
            value++;
        }
        dac.send(buffer, bufferLen);
    }
}
\end{lstlisting}

\subsubsection{Button}
Der Buttonport hat 2 Methoden um auf die Taster zu reagieren.

\lstinline|getState| wird eine GPIO-pinnummer übergeben und als 
Rückgabe gibt es 1 zurück, wenn der Pin mit dieser Nummer LOW ist.
Also, wenn der Taster an diesem Pin gedrückt wird. 
\lstinline|getState| gibt 0 zurück, wenn der Taster nicht gedrückt ist.

Diese Methode ist dafür geeignet um zu sehen, ob ein Taster über längere
Zeit gedrückt wird. Um nur zu schauen, ob ein Taster kurz oder überhaupt
gedrückt wurde, ist \lstinline|readQueue| die bessere Wahl.

Bei jedem Drücken eines Tasteres, also bei jeden Fallen von HIGH 
zu LOW an einem Pin mit einem Taster wird die Nummer des Pins 
in eine Queue gepackt.
Die Queue kann mit \lstinline|readQueue| ausgelesen werden.
Hierbei gibt es zwei Dinge zu beachten.

1. Entprellung. Wenn ein Taster gedrückt wird, geht der Pegel des 
zugehörigen Pins nicht einfach auf LOW. Sondern er springt ein paar mal 
zwischen LOW und HIGH. Um ein mehrfaches Lesen des Tasters bei
einmaligem Drücken zu verhindern wird zwischen 2 Eingaben 
eine mindest Zeitabstand von 200ms festgelegt.

2. Threadsavety. Wenn zum Beispiel Taster 1 gedrückt wird und in 
2 verschiedenen Tasks 
\lstinline|getQueue| aufgerufen, dann erhält nur eine der beiden 
den Wert 1 und leert die Queue.

\subsubsection{Encoder}
Encoder ist der Adapter für den Drehgeber. Dazu wurden aus dem 
ESP-Beispielcode \cite{espEncoder} für Encoder die wichtigsten Teile kopiert.
Dieser nutzt die Pulsecontrol-API. 

Encoder hat eine Funktion \lstinline|getValue|, welche ein Wert 
zurückgibt. Dieser Wert ist zu Begin 0 und erhöht sich um Eins, wenn der 
Drehgeber um einen Schritt mit dem Uhrzeigersinn gedreht wurde. 
Gegen den Uhrzeigersinn veringert sich der Wert.

Mit \lstinline|resetValue| wird der Wert auf 0 zurückgesetzt.
% Das ist nötig, wenn Encoder zum Ändern einer Variable genutzt wird,
% aber zwichenzeitlich auch für etwas anderes.
Um eine Variable zu ändern, kann in einer Schleife der aktuelle Wert mit
dem Wert aus der vorherigen Itteration verglichen werden. 
Jenachdem wie sich der Wert ändert, wir die Variable geändert. 

\begin{lstlisting}[language=C++, 
                   frame=single, 
                   caption={Beispiel Variable ändern mit Encoder},
                   captionpos=b]
    int lastValue= 0;
    int Variable;
    while(1) {
        if(lastValue < encoder.getValue()) { 
            Variable++;
        }
        if(lastValue > encoder.getValue()) {
            Variable--;
        }
    }
\end{lstlisting}

Dieses Pattern wird häufig mit einer oberen und unteren Grenze verwendet.
Deshalb gibt es in Encoder eine Funktion changeExternalVariable,
welcher man eine Variable ein Minimum, ein Maximum und eine 
Schrittweite gibt. Die Schrittweite gibt an um wieviel die 
Variable erhöht wird.


\subsubsection{Screen}

Der Zugriff auf den OLED-Bildschirm erfolgt über Einen Biblithek
von voidlooprobotech \cite{voidloop2026ssd1306}.

Der Port hat kann mit Methoden mit dem Prefix draw Dinge wie einen 
Punkt, Strings, Zahlen oder Bitmaps malen.

Bitmaps sind uint8\_t-Array, wobei hier jedes Bit ein Pixel darstellt.


\subsubsection{Andere nützliche Adapter}
Zwei weitere Adapter sind Util und Timer.

Util implementiert die Funktionen millis und delay wie sie bei
Arduino genutzt werden, sie dazu \cite{arduinoMillis} und \cite{arduinoDelay}.

Timer ist ein Wert, der bei 0 startet und alle 16 ms incrementiert wird.
Die Funktion getValue gibt diesen Wert zurück und setValue setzt den 
Wert auf einen beliebigen Wert.
16 ms wurden gewäht, da der Timer so später genutzt wird, aber eine 
mögliche Verbesserung wäre zu Begin das Inkrementationsinterval 
zu übergeben.

Es wurde ein Adapter für die  RGB-LED auf dem ESP32-S3-Board implementiert.

\subsubsection{Mögliche Erweiterung: freeRTOS Adapter}

FreeRTOS \cite{freeRTOS} ist ein Echtzeitbetriebssystem für Mikrocontroller.
Es ist in der ESP-IDF enthalten und wird auch genutzt, um mehrere Tasks 
gleichzeitig auszuführen.
Um den Kern FreeRTOS unabhängig zu machen, könnte ein Adapter für FreeRTOS
implementiert werden. Dieser müsste lediglich die Funktionen zum Erstellen 
von Tasks implementieren.

\subsection{Kern}

Der Kern der Anwendung besteht aus 3 Komponenten. Das sind
\begin{enumerate}
    \item die DSV-Bibliothek, welche
            wie oben beschrieben, als eine Klasse namens Signal implementiert ist.
    \item Eine 
            Erweiterung dieser Klasse namens Sound, welche ein Audiosignal darstellt.
    \item Der Synthesizer, welche die Soundklasse nutzt, um mithilfe der 
        Hardware einen Synthesizer zu implementieren. 
        Dazu gehören auch Envelope und Menu.
\end{enumerate}
